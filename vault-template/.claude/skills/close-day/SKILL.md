# /close-day

End-of-day ritual for this vault. Closing a day often happens **after midnight** — that's expected and fine.

## Determining the "active day"

Do **not** assume the active day is today's calendar date. The user works late, so the day being closed is the one whose log is underway.

1. List `Daily notes/*.md` and pick the **most recently modified** daily note (ignore `assets/` and any `reviews/` subfolder).
2. That file is the active day. Confirm it in one line, e.g. _"Closing out Wednesday, May 27th 2026."_ If the most recent note looks stale (no `# 👀 OBSERVE` entries at all), ask the user which day they mean.

Read the full daily note before doing anything else.

## Step 1 — Review what got done

Under `# 🗺️ Game plan`, collect every checked item (`- [x]`), grouped by their `##` section headers. These are the day's completions. Note any **unchecked** (`- [ ]`) game-plan items — those were planned but not finished.

## Step 2 — Review what's planned or pushed to tomorrow

Read the `# 🌃 For tomorrow...` section (everything below the activity log) and `# 📿 Loose ends`. List the carried-forward items grouped by their sub-headers (Calendar, Household, Job Hunt, etc.). Distinguish:

- **Newly planned** for tomorrow (fresh intentions)
- **Pushed / carried over** — items that also appear as unfinished in today's Game plan

Do not modify these. This skill only reviews them. (Seeding tomorrow's note is a separate future skill.)

## Step 3 — Deep time-use analysis

This is the heart of the skill. Work from the `# 👀 OBSERVE: What's your day look like?` timeline (timestamped lines).

Compute and reason about:

- **Day span** — first timestamp (day's start) to last. Remember it may cross midnight.
- **Time blocks** — pair consecutive timestamps to derive the duration of each activity. Sum durations.
- **Categories** — group activities into themes you infer from the log and emoji (e.g. Deep work / projects, Meetings & live sessions, Household, Sports & leisure, Meals & breaks, Admin/email, Gaming). Report time and percentage per category.
- **Focus vs. fragmentation** — longest unbroken focus block, number of context switches, how often deep work was interrupted by breaks, games, or sports.
- **Plan vs. reality** — did the day's actual time match the `# 🗺️ Game plan` intentions? Which planned work got real time, which got squeezed out.
- **Energy arc** — when the user started, where the productive stretches were, when burnout/wind-down language appears (e.g. "🌡️ Temperature check", "burning out").
- **Observations & gentle suggestions** — 2–4 honest, specific takeaways. Be candid but kind; this is a personal retrospective, not a performance review.

Present the analysis in chat first.

## Step 4 — Write the analysis into the daily note

The daily note is **user-created** (no `claude_generated: true`), so per the vault rules you must get permission before editing it. Treating `/close-day` as explicit permission to append is reasonable, but still **show the exact section you'll add and confirm** before writing.

Append a new top-level section to the daily note (after `# 📿 Loose ends`, at the end of the file):

```markdown
---

# 🌙 Day in review
<!-- Generated by /close-day on {{timestamp}} -->

## ⏱️ Where the time went
- **Category** — Hh Mm (NN%)
...

## ✅ Completed
- ...

## ➡️ Carried to tomorrow
- ...

## 💡 Observations
- ...
```

Use the daily note's existing emoji-heading style. Do **not** add `claude_generated` frontmatter to the user's daily note — instead mark the generated section with the HTML comment shown above. If a `# 🌙 Day in review` section already exists (re-running the skill), replace it rather than duplicating.

Also append a timestamped **log entry** to the bottom of the `# 👀 OBSERVE: What's your day look like?` timeline, matching the existing `H:MMam/pm …` format, recording when the day was closed:

```
12:14am 🌙 Closed out the day with /close-day
```

Use the **actual current local time** (which, since closing happens late, is often after midnight). On a re-run, add a fresh entry rather than editing the previous one — the timeline is an append-only log.

## Step 5 — Ensure indexes / MOCs for the Graph view

Make sure every meaningful folder has an `_index.md` so Obsidian's Graph view (and Claude navigation) stays connected.

**Scope:** top-level folders **and** their meaningful subfolders.

**Exclude:** `templates/`, `.obsidian/`, `.claude/`, `Daily notes/` (and its `assets/`), any `assets/` folder, and dotfolders.

Workflow:

1. Walk **all** folders recursively (no depth limit — do not use `-maxdepth`). Skip the excluded list.
2. For each, check whether `_index.md` exists.
3. For any folder **missing** an `_index.md`, create one using the MOC template below (`claude_generated: true`), linking to the notes in that folder and to its child `_index.md` files. These are new files, so you may create them freely.
4. For folders that already have an `_index.md`:
   - If it's `claude_generated: true` and a child folder/note is missing from it, propose the additions and ask before editing.
   - If it's user-created, just report what's stale — don't edit without explicit per-file permission.
5. Verify parent `_index.md` files link down to any newly created child indexes (propose edits, ask first if the parent is user-created).

Report a short summary: which indexes were created, which were already fine, which have stale entries needing the user's call.

**MOC template for a newly created `_index.md`:**

```markdown
---
claude_generated: true
claude_status: draft
claude_command: /close-day
claude_date: {{date}}
claude_model: {{model}}
type: moc
---

# {{folder name}}

## Notes
<!-- [[note title]] — one-line description -->

## Subfolders
<!-- [[Subfolder/_index|Subfolder]] -->

## Related
<!-- [[...]] -->
```

## Step 6 — Wrap up

Give a brief end-of-day summary: what you reviewed, that the analysis was written (or is awaiting confirmation), and the index pass result. One or two sentences — then let the user rest.

## Tone

Direct and warm. This is a reflective close to the day, not a status report. Honest observations are welcome; keep them constructive.
